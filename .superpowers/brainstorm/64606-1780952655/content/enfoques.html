3 enfoques posibles

Cada uno tiene diferente complejidad y capacidades

A

React + Express proxy Recomendado

El backend en Express guarda el API token de Jira en .env y actúa como proxy. El frontend React llama al backend local, nunca expone credenciales. Gráficos con Recharts.

Pros

  • Simple de arrancar
  • Seguro (token en backend)
  • Datos siempre frescos de Jira

Contras

  • Depende de conexión a Jira en tiempo real
B

React directo a Jira API (sin backend)

El frontend llama a Jira Cloud directamente desde el browser.

Pros

  • Más simple de configurar

Contras

  • Token expuesto en el browser
  • CORS bloqueado por Jira Cloud
  • No recomendado
C

React + Express + SQLite (con historial)

Igual que A, pero un job periódico guarda datos en SQLite. El tablero lee del cache local — más rápido y con datos históricos.

Pros

  • Historial propio de métricas
  • Rápido (lee de DB local)
  • Funciona sin conexión

Contras

  • Más complejo de configurar
  • Requiere mantener la DB
